# ブラウザテスト（tests/e2e）

`tests/` の他のテスト（`node tests/check.js` など）は Node.js だけで動きます。
ここにあるテストは、実際のブラウザ（Playwright + Chromium）で画面を動かして確かめます。

| ファイル | 内容 |
| --- | --- |
| `share.js` | 結果画面の「画像を保存・シェアする」を中心に確かめます（138件）。8タイプのシェア画像の中身（下の誘導・本番のアドレス・タグの並びと重なり）、共有メニュー（成功・キャンセル・失敗・連打）、ダウンロードと保存した PNG、端末ごとの案内文（iPhone / Android / アプリ内ブラウザ）、コピー（コピーした文章とアドレス）、今日の占いの「シェアする」で送るアドレス。あわせて、タイプ保存の案内、保存したタイプの今日の占いへの反映、日付のお試し表示（`?preview-date=`）も見ます |
| `types.js` | 全8タイプの確認用の回答（`tests/type-answers.js`。一覧は README.md の「全8タイプの確認用の回答」）で、トップから実際に14問に答え、結果画面のタイプ名・絵文字・サブタイプコードと保存したタイプが目的どおりかを確かめます。各質問で、画面の質問の番号・文・選択肢の並びがデータと同じことも見ます。あわせて、320・375・390px で、タイプ名・キャッチコピー・お守りの言葉・質問が言葉のまとまりの境目でだけ改行し、横にはみ出さないことを見ます（28件）。iPhone の Safari は `word-break: auto-phrase` に対応していないため、Chromium でも auto-phrase を止めた状態で確かめます。WebKit（Safari）そのものでは確かめていません |
| `sw-update.js` | 公開中の版（既定は `origin/main`）から今の版へ更新したときの確認です（12件）。古い版で診断と今日の占いを保存してから、同じアドレスで中身を今の版に入れ替え、Service Worker が新しい版に替わって古いキャッシュが消えること、保存した記録（localStorage）が変わらずに残ること、トップのタイプと今日の占いが同じこと、今日の一枚の入口が通常のアドレスで出てプレビューの案内が出ないこと、オフラインでも新しい版が出ることを見ます。古い版は `git archive` で一時フォルダに取り出し、終わったら消します（`git fetch origin main` をしておく） |

## 必要なもの

- Node.js 18 以上（v22 で確認）
- `playwright` パッケージ（v1.56 で確認）と、Playwright 用の Chromium

このリポジトリには `package.json` を置いていません。サイトは静的ファイルだけで動くためです。
Playwright は、テストを動かす環境に別に入れてください。

```sh
# どこか一つ（リポジトリの外がおすすめ）に入れて、NODE_PATH で見えるようにする例
npm install --prefix ~/oshi-luna-tools playwright
npx --prefix ~/oshi-luna-tools playwright install chromium
export NODE_PATH=~/oshi-luna-tools/node_modules
```

`require('playwright')` が通る環境（Playwright がすでに入っている環境など）なら、そのまま動きます。

## 実行

リポジトリのいちばん上で実行します。

```sh
node tests/e2e/share.js                          # リポジトリを 127.0.0.1 の空きポートで配信してテスト（サーバーの起動は不要）
node tests/e2e/share.js http://localhost:8000/   # すでに起動しているサーバー（python3 -m http.server 8000 など）を使う。末尾の / まで書く
node tests/e2e/share.js "" ./tmp-share-out       # ダウンロードした PNG と画面の画像を、指定したフォルダに残す
node tests/e2e/types.js                          # 全8タイプの確認用の回答で診断（サーバーの指定は share.js と同じ）
node tests/e2e/sw-update.js                      # 公開中の版（origin/main）から今の版への更新（古い版のコミットも指定できる）
```

- 結果は1行ずつ `PASS` / `FAIL` で表示され、最後に `0 FAIL / 138` のように件数が出ます。失敗があると終了コードは 1 です
- 実行には1〜2分かかります
- ダウンロードした PNG と画面の画像は、フォルダを指定しなければ一時フォルダに作り、終わったら消します。リポジトリには何も書きません（3つめの例のようにフォルダを指定した場合は、そのフォルダをコミットしないでください）
- サーバーにつながらないなど途中で止まったときは、エラーを表示して、すぐに終了コード 1 で終わります

## テストのしくみ

- **共有メニュー**：`navigator.share` は本物を使いません。テスト用に差し替えて、成功・キャンセル（AbortError）・失敗（NotAllowedError / DataError）を再現します。共有できない環境は、差し替えずに Chromium の状態のまま確かめます
- **端末**：iPhone 13 / iPhone SE / Pixel 7 などは、Playwright の端末設定（画面の大きさと User-Agent）を使った再現です。Safari や Android の Chrome そのものではありません
- **Google アナリティクス**：`googletagmanager.com` への通信は空のスクリプトに差し替え、実際には送りません
- **ダウンロードした PNG の確認**：次の4つのダウンロードで、保存されたファイルを検証します
  - iPhone で共有できない場合
  - 共有メニューの失敗（notallowed）のあと
  - 共有メニューの失敗（fail）のあと
  - Android で共有できない場合

  確かめること：
  - 空でないこと（10KB より大きい。実際は約1.1MB）
  - PNG の署名、すべてのチャンクの CRC、IHDR、IEND がそろっていること
  - 画像データ（IDAT）を展開した大きさが、1080×1920 の画像の大きさと一致すること（最後まで読める）

## ブラウザを LANG=C.UTF-8 で起動する理由

`share.js` は、ブラウザを `LANG=C.UTF-8` で起動します（`chromium.launch({ env: { ...process.env, LANG: 'C.UTF-8' } })`）。

以前、次の4件がいつも失敗していました。

1. 「画像を保存・シェアする」（共有できない）→ PNG をダウンロード・日本語のファイル名
2. 共有メニューが失敗（notallowed）→ 次はダウンロードに切り替え
3. 共有メニューが失敗（fail）→ 次はダウンロードに切り替え
4. Android・ダウンロード → ファイル名・ダウンロード一覧で確認の案内

調べてわかったこと：

- 4件とも、ダウンロード自体は起きていて、中身も正しい PNG でした。ずれていたのはファイル名だけです。`推しルナ占い_〇〇.png` の代わりに `download` になっていました。案内文・手順の切り替え・共有の回数は合っていました
- アプリのコードを使わずに試しても同じでした。blob の URL と `download` 属性だけで試すと、英数字のファイル名はそのまま保存され、日本語のファイル名だけが `download` になりました（iPhone / Android / PC の設定、接続先のアドレスにかかわらず同じ）
- テストを動かした環境では `LANG` が空で、ロケールは C/POSIX でした。Linux の Chromium はダウンロードのファイル名をロケールの文字コードに変換するため、日本語を変換できず `download` に置き換えていました。同じ確認を `LANG=C.UTF-8` で起動すると、日本語のファイル名がそのまま保存されました
- つまり原因は、テストの実行環境（ブラウザを起動するときのロケール）です。アプリのファイル名の付け方やダウンロードの処理は正しく、アプリは変更していません

結果：

- 元のテスト（109件）は、期待値を1つも変えず、ブラウザの起動設定を `LANG=C.UTF-8` にしただけで 109件すべて合格しました
- そのうえで、上の4つのダウンロードについて PNG の検証を1件ずつ追加し、113件すべて合格しました
- その後、シェア画像の下を「無料の推し活タイプ診断」＋本番のアドレス（`https://oshi-luna.com/`）＋タグに変えたのに合わせて、8タイプそれぞれに2件（画像のアドレスは本番だけで、開いているアドレスは入れないこと／誘導・アドレス・タグが重ならず枠の中に収まること）を追加し、129件すべて合格しました
- さらに、コピーする文章のアドレスも本番にそろえたのに合わせて、コピーした文章を確かめる1件（タイプ名・キャッチコピー・#推しルナ占い はそのまま、アドレスは `https://oshi-luna.com/` だけで、開いているアドレスは入れない）を追加し、130件すべて合格しました
- さらに、今日の占いの「シェアする」（`navigator.share`）のアドレスも本番にそろえたのに合わせて、8件を追加し、138件すべて合格しています（`127.0.0.1` と `localhost` の2つのアドレスで開いて確認）
  - 「画像を保存・シェアする」の4つの結果（ok / abort / notallowed / fail）それぞれで、共有メニューに渡すのが画像ファイルだけであること（4件）
  - 今日の占いの「シェアする」を、`?preview-date=` と `#` のついたアドレスで開いて押したとき（共有メニューあり／なし→コピー）：送るアドレスが `https://oshi-luna.com/` で、タイトルと占いの文章は元のままであること、開いているアドレスが入らないこと（4件）

## 未確認のこと

このテストは Linux の Chromium で動かしたものです。次のことは確かめていません。

- iPhone の Safari（実機）：日本語のファイル名で保存されるか。ダウンロードの確認表示と、保存先が「ファイル」アプリになるか。共有メニューの「画像を保存」から写真アプリに入るか
- Android（実機）の Chrome など：日本語のファイル名でダウンロード一覧に入るか。本物の共有メニューの動き
- 本物の共有メニュー（OS の共有シート）：テストでは `navigator.share` を差し替えているため、実際のメニューの表示や、選んだアプリでの保存は確かめていません
