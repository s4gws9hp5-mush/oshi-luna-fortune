# 推しルナ占い 🌙🐈

「推しを好きな気持ちも、自分のことも大切に。」

推し活をしている人が、毎日の占いを楽しみながら、自分らしい推し活スタイルを知れるスマートフォン向けサイトです。

- 外部API・外部フォント・サーバー・有料サービスを使わない静的サイト（HTML / CSS / JavaScript のみ）
- ビルド不要。GitHub Pages にこのフォルダをそのまま置けば公開できます
- 結果はこの端末のブラウザ（localStorage）にだけ保存されます。ブラウザのデータを消すと保存した結果も消えます

## 2つの体験

### 今日の推し活占い（毎日）

トップの「今日の推し活占いを見る！」を押すと、約1秒の読み込み演出のあとに表示されます。

- 推し活タイプ診断がまだの人には、押したときに診断の案内（ポップアップ）を出します。「🎀 推し活タイプ診断をする」で診断へ（途中まで答えていれば続きから）、「このまま今日の占いを見る」で診断せずに占いへ、×や背景のタップでトップに戻ります。診断済みの人には出しません

- 日付は日本時間で判定し、毎日0時に切り替わります（端末のタイムゾーンが日本以外でも同じ）
- 運勢は一人ひとりちがいます。ブラウザごとにランダムなID（下の「ブラウザごとのID」）を作り、「日本時間の日付＋ID」から計算します
- 同じブラウザなら、同じ日は何度見ても同じ結果です（日付とIDだけで決まる計算なので、保存がなくても同じ結果になります。さらに、その日に最初に出た結果も保存しています）
- 表示内容：今日の運勢（★1〜5）・今日のあなたへのメッセージ・ラッキーアクション2つ・ラッキーカラー（色見本つき）/アイテム/時間帯・白猫からのお守りメッセージ
- 推し活タイプを診断済みなら、メッセージ・ラッキーアクション・お守りの言葉がタイプに合わせた内容になります。運勢の★・運勢文・ラッキー・お守りはタイプを使わずに決めます（タイプで有利・不利が出ないように。同じ日にタイプを変えても変わりません）
- 占いを見たあとにその日に診断したときは、その日の占いは変えず、翌日からタイプに合わせた内容になります

#### 内容の選び方と候補の数

★の数は「日付＋ID」から作る乱数で決まります（出やすさは ★1:6%・★2:16%・★3:30%・★4:32%・★5:16%。前の日と同じ★になることは約25%あります）。
それ以外は、候補ごとにIDで決まる並び（シャッフルした順番）で1日ずつ順番に出すので、同じ人には候補の数と同じ日数のあいだ同じものが出ず、前の日と同じ内容が続くこともありません（`js/fortune.js` の `cycle`）。同じ日の別の人とは、並びがちがうのでほとんどの項目がちがう内容になります（偶然同じになることはあります）。下の表の日数は、同じ人の場合です。

| 項目 | 候補の数 | 同じものがまた出るまで |
| --- | --- | --- |
| 運勢文 | ★ごとに6（全30） | 6日以上 |
| ラッキーカラー | 13 | 13日 |
| ラッキーアイテム | 14 | 14日 |
| 時間帯 | 9 | 9日 |
| ラッキーアクション（未診断・1日2つ） | 25 | 同じ組み合わせは25日、1つずつは12日以上 |
| 今日のメッセージ（未診断） | 14 | 14日 |
| お守り（全員共通） | 31 | 31日 |
| タイプ別ラッキーアクション（1日2つ） | 各タイプ9 | 同じ組み合わせは9日、1つずつは4日以上 |
| タイプ別メッセージ | 各タイプ10 | 10日 |
| タイプのお守りの言葉 | 各タイプ5（`omamori.charm` ＋ `daily.charms`） | 5日 |

候補を増やすときは `js/data.js` の配列に足すだけで、並びは自動で作られます（並びが変わるので、その日以降の内容も入れかわります。すでに見た日の占いは保存済みなので変わりません）。
- 直近の占い（最大7日分）を端末に保存し、同じ日の結果を固定するのに使います

### 推し活タイプ診断（固定タイプ）

既存の10問に答えると、8つのタイプのどれかに決まります（このあとにサブタイプコードの4問が続きます）。日付や乱数は使わないので、同じ回答なら必ず同じタイプです。

| タイプ | |
| --- | --- |
| 🌙 月夜のおひとりさま鑑賞家 | 📣 ときめき全力応援隊長 |
| 📷 思い出アルバムコレクター | 💬 推し語りコミュニケーター |
| 🌱 そっと寄りそう見守りさん | 🎨 ときめき探究クリエイター |
| ☁️ マイペースな癒やし系ファン | 🔭 情報キャッチの星読みリサーチャー |

- 判定：選んだ選択肢の main のタイプに2点、sub のタイプに1点。合計点が最も高いタイプになります
- 同点のとき：main に選ばれた回数 → main に選ばれた質問の早さ → 点が入った質問の早さ → `TYPE_ORDER` の順
- 各タイプは main・sub ともにちょうど5回ずつ登場するので、どのタイプも出やすさはほぼ同じ（11〜13%）です
- 回答は1問ごとに保存され、途中で閉じても「続きから」再開できます
- 診断済みの人がもう一度診断して別のタイプになったときは、「保存する」を押すまで前のタイプのままです
- 旧4問版の診断の保存データ（`oshi-luna-last`）は消さずに残していますが、新しいタイプとしては使いません

### サブタイプコード（4つの軸）

8タイプとは別に、4つの軸の文字を並べた「サブタイプコード」（例：`EFIS`）を出します。8タイプの判定には使いません。

| 軸 | 文字 |
| --- | --- |
| 愛情表現 | E 伝える ／ W 見守る |
| 応援スタイル | F 体験型 ／ H マイペース型 |
| 気持ちの整理 | I 直感 ／ A 分析 |
| 楽しみ方 | S 共有 ／ P 自分時間 |

- 診断は14問：既存の10問（8タイプ）のあとに、軸ごとの質問を1問ずつ（Q11〜Q14、`AXIS_QUESTIONS`）
- 判定（`js/fortune.js` の `diagnoseAxes`）：既存の10問と追加の4問を両方使い、軸ごとに両側（例：E と W）の点数を合計します
  - 追加の4問は 4点（Q12-B「行ける日は現地、ほかは配信」だけ 2点）。既存の10問は、軸とはっきり関係する選択肢が 2点、やや関係する選択肢が 1点（`js/data.js` の `AXIS_TAGS`）。関係のはっきりしない選択肢は使いません
  - 両側の点数を、それぞれ「その側の平均的な点数」（関係する質問ごとの、4つの選択肢の点数の平均の合計）で割ってから比べます。選択肢の数のちがいで、片方の文字が有利にならないようにするためです
  - 左側の割合＝（左＋0.25）÷（左＋右＋0.5）。0%・100% のような極端な値になりにくくする補正です（`AXIS_RULES`）
  - 割合が 45〜55% なら **X（バランス型）**、56〜65% なら「やや〜寄り」、66% 以上ならその側の文字
  - 結果画面に「伝える 62%／見守る 38%」のように表示します。回答から出した傾向の目安で、確率ではありません
  - 既存の10問の答えが保存されていない古いデータは、追加の4問だけで決まります（X にはなりません）
  - 画面に出すコードは、保存した文字ではなく保存した答えから毎回計算します。前の方式で保存したサブタイプも、新しい方式で表示されます
- 8タイプは、これまでどおり既存の10問の答えだけで決まります（`tests/check.js` で、全1048576通りの判定結果が変わっていないことを確認）
- サブタイプの項目がない古い診断結果の人は、結果画面の「🧭 サブタイプコードを調べる（4問）」で4問だけ答えられます。保存済みの10問の答えと合わせて判定し、8タイプは変わりません
- コピーするシェア文に「サブタイプコード：EFIS」を入れます（シェア画像は変えていません）
- 今日の占いには使いません

タイプ別の絵は正方形の透明PNGです。差し替えるときも正方形にすると、表示がそろいます。

- 絵を差し替えるときは、新しいファイル名にします。古い絵がブラウザや Service Worker のキャッシュに残らないようにするためです。あわせて `sw.js` の `CACHE` の名前（今は `oshi-luna-v8`）と `CORE` の一覧も変えます
- 応援隊長（`cheer-penlight-sparkle.png`：左上の余計な線を削除した版）・コミュニケーター（`talk-heart-bubble.png`：耳の青い汚れを修正した版）・癒やし系（`heal-cushion-mug-cozy.png`：左の煙を削除し、胴体とクッションを整えた版）の絵も、いただいた背景透過PNG（1254×1254・RGBA）の画素をそのまま使っています
  - 見た目を変えないロスレス圧縮だけ行いました（応援隊長 1,658KB → 973KB、コミュニケーター 1,771KB → 884KB、癒やし系 1,254KB → 674KB）。全画素（透明な部分の色も含む RGBA）が元のPNGと同じことを `tests/check.js` で確かめています
  - 圧縮のときに、画素と関係のない付加情報（応援隊長の来歴情報 C2PA の `caBX`、ほかの2枚の EXIF〔向きは回転なし〕など）は入らなくなりました。色の扱いを示す `sRGB` は残しています
  - 絵の幅・中心の位置は前の絵とほぼ同じなので、表示の調整はしていません（ほかのタイプと同じ大きさ・位置）
- 星読みリサーチャーの絵（`research-telescope-book.png`、1254×1254・RGBA）は、いただいた背景透過PNG（星座なし版。最終採用）の画素をそのまま使っています
  - 描き直し・縮小・色の変更はしていません。見た目を変えないロスレス圧縮だけ行い、899KB から 759KB にしました。全画素（透明な部分の色も含む RGBA）が元のPNGと同じことを `tests/check.js` で確かめています
  - 元のPNGに入っていた来歴情報（C2PA の `caBX` チャンク、約22KB）は、圧縮のときに入らなくなりました。画素とは関係のない付加情報です
  - 絵が下と左に寄っていて（上に余白）、白猫が小さめに見えるので、表示だけ中央に寄せて少し大きくしています（画像のファイルは変えていません）
    - ふつうの表示：右へ6%・上へ13.3%・1.12倍。画面は `css/style.css`、シェア画像は `js/data.js` の `imageFit`（`{ scale: 1.12, x: 0.06, y: -0.133 }`）で、同じ値を指定しています
    - 結果画面の丸い絵も同じ位置（丸の中央）です。右下の絵文字の丸（🔭）が本の右端にかからないよう、リサーチャーのときだけ丸を外側（右へ10px・下へ12px）に動かしています。丸の大きさはほかのタイプと同じです（`css/style.css` の `#type-emblem[data-type="research"] .type-emoji`。`js/app.js` が結果画面の丸に `data-type` を入れる）
  - 調整したあとも、望遠鏡・耳・しっぽ・本は円の枠の内側に収まります

### 推し活タイプのシェア画像

タイプ結果の「📸 結果をシェアする」で、「推し活タイプ取扱説明書」の画像（1080×1920・ストーリーズと同じ縦長の PNG）を、ブラウザの中で作ります（`js/share-card.js`）。

入る内容：サービス名、「推し活タイプ取扱説明書」のリボン、「あなたの推し活タイプは」、タイプ専用の白猫（いちばん大きく）、タイプ名（タイプの色のマーカーつき）、キャッチコピー（吹き出し）、4つのパネル（どんな人？＝`card.traits`／推し活で輝くところ＝`strengths` の最初の2つ／取り扱いのコツ＝`card.care`／仲良くなるヒント＝`card.friend`）、「あなたは何タイプ？」「無料の推し活タイプ診断」とその直下のサイトのアドレス（白い角丸の上に `https://oshi-luna.com/`）、#推しルナ占い。アドレスは、プレビューやローカルで画像を作っても、いつも本番の `https://oshi-luna.com/` を入れます（`js/share-card.js` の `SITE_URL`）。

- パネルのふち・見出し・白猫の輪・マーカーは、タイプの色（`TYPES` の `color`）で塗ります
- 月・星・リボン・ハートの飾りは、文字にかからない場所（白猫の左右・見出しのアイコン）にだけ置きます
- 文字は見出し28px・本文30px以上。文章が長いタイプは、余白 → 白猫の順に少し小さくして収めます。短いタイプは、白猫を大きくして余白をそろえます
- 改行は、句読点や助詞のあとなど自然な位置で、行の長さがそろうように選びます。途中で分けたくない言葉は `KEEP_WORDS` に足せます

#### 画像の保存・共有

ボタンは「📥 画像を保存・シェアする」と「タイプ名とURLをコピー」の2つです。コピーする文章のアドレスも、プレビューやローカルで開いていても、いつも本番の `https://oshi-luna.com/` です（`js/app.js` の `SITE_URL`）。

共有する内容のアドレスは、どの経路でも、開いているページ（プレビュー・ローカル・`?preview-date=` など）ではなく本番の `https://oshi-luna.com/` です。

- シェア画像の中のアドレス：`js/share-card.js` の `SITE_URL`
- 「タイプ名とURLをコピー」の文章：`js/app.js` の `SITE_URL`
- 「📥 画像を保存・シェアする」：共有メニューには画像ファイルだけを渡します（アドレスや文章は渡しません）
- 今日の占いの「今日の占いをシェアする」：共有メニューの `url` に `https://oshi-luna.com/`。共有メニューがないときにコピーする文章も、占いの文章のあとに同じアドレス

- 画像ファイルの共有に対応したブラウザ（`navigator.canShare({ files })`）では、生成した画像ファイルだけを共有メニューに渡します。iPhone ではメニューの「画像を保存」で写真アプリに保存でき、LINE などを選べばそのまま送れます
- 対応していないブラウザでは、同じボタンで画像ファイルをダウンロードします（iPhone では「ファイル」アプリ、Android ではダウンロードフォルダ）。写真アプリに入れる方法として、画像の長押しも案内します
- 共有メニューが開けなかったときは、次に押したときからダウンロードに切り替えます
- ファイル名は「推しルナ占い_タイプ名.png」
- 手順は iPhone／iPhone のアプリ内ブラウザ（LINE など）／Android／その他 で出し分けます
- 保存できたかどうか、共有メニューで何を選んだかはブラウザから分からないため、「保存しました」とは表示しません。キャンセルしたときは、キャンセルしたことだけを表示します

### 翌日の占いを試すとき（日付のお試し表示）

URL の最後に `?preview-date=2026-10-19` のように日付を付けると、このブラウザ（ID）のその日の「今日の推し活占い」を表示できます（保存中のタイプも反映）。
お試し表示の結果は保存されず、IDも変わりません。ふつうに開けば、いつもどおり日本時間の今日の占いです。例：`https://s4gws9hp5-mush.github.io/oshi-luna-fortune/?preview-date=2026-10-19`

## 文章や質問を直すとき

すべて `js/data.js` にあります。

| 直したいもの | 場所 |
| --- | --- |
| タイプの説明（9項目） | `TYPES` の各タイプ |
| タイプ別の今日のメッセージ・アクション・お守りの言葉 | `TYPES` の各タイプの `daily`（`actions`・`messages`・`charms`） |
| 質問と配点 | `QUESTIONS`（`main` に2点・`sub` に1点） |
| 今日の運勢・お守り・未診断の人へのメッセージ | `LUCK`・`DAILY` |
| ラッキーカラー・アイテム・時間帯 | `LUCKY_COLORS` などと、色コード `LUCKY_COLOR_CODES`・アイコン `LUCKY_ITEM_ICONS` / `LUCKY_TIME_ICONS` |

文章を直したら `node tests/check.js` を実行してください。空欄・使い回し・色コードやアイコンの漏れ・配点の偏り・「必ず」「当選」などの断定表現を自動で確認します。

### 改行の区切り（言葉のまとまり）

iPhone の Safari は、言葉の切れ目で改行する指定（`word-break: auto-phrase`）に対応していません。そのため、短い見出しのような文は、改行してよい「言葉のまとまり」を `js/data.js` に持たせています。画面では、まとまりの境目でだけ改行します（`js/app.js` の `setPhrased`、`css/style.css` の `.phrased .phrase`）。

| 文 | 区切り |
| --- | --- |
| タイプ名・キャッチコピー・お守りの言葉 | `TYPES` の各タイプの `phrases`（`name`・`catch`・`charm`） |
| 質問（14問） | `QUESTIONS`・`AXIS_QUESTIONS` の各質問の `phrases` |
| タイプ紹介ページのキャッチコピー | `types/index.html` の `guide-type-catch` の中の `<span class="phrase">`（`phrases.catch` と同じ） |

- タイプ名の区切りは、トップの8タイプ一覧（`index.html`）とタイプ紹介ページのタイプ名と同じです
- タイプ名は、トップの診断済みカード・結果画面・今日の占い（「〇〇のあなたへ」「〇〇のあなたにおすすめ」、お守りの「〇〇のあなたへ：」）・診断後の確認や案内の文でも、この区切りで表示します
- 文を直したら、`phrases` も同じように直してください。`node tests/check.js` で、つなげると元の文と同じか・トップ一覧や types/ と同じかを確かめます。`node tests/e2e/types.js` で、320・375・390px で言葉の途中で改行しないか・横にはみ出さないかを確かめます（Chromium で auto-phrase を止めた状態。Safari そのものでは確かめていません）
- 今日の占いの本文（メッセージ・お守りの文、全部で約165種類）は、数行の文章なので区切りを持たせていません。iPhone では日本語のふつうの折り返しになります

### 保存データ（localStorage）

| キー | 中身 |
| --- | --- |
| `oshi-luna-type` | 推し活タイプ診断の結果 `{ version: 2, type, sub, answers（10問）, date, subtype? }`。`subtype` は `{ version: 1, answers（Q11〜Q14の4問）, code }`（ない古いデータもそのまま使えます） |
| `oshi-luna-quiz` | 診断の途中の回答（14問のうち答えたところまで。10問だけの古い途中データも続きから使えます） |
| `oshi-luna-subtype-quiz` | 診断済みの人が、サブタイプの4問だけ答えている途中の回答 |
| `oshi-luna-daily` | 今日の推し活占いの履歴（最大7日分） |
| `oshi-luna-a2hs` | ホーム画面への追加の案内を閉じたかどうか（表示の設定だけ） |
| `oshi-luna-device` | 今日の運勢を一人ひとり変えるためのランダムなID（下を参照） |

保存先はこの端末のブラウザの localStorage だけです。sessionStorage・Cookie・サーバーへの保存は使っていません。
ホーム画面に追加してもバックアップにはならず、別の端末には引き継がれません。iPhone では、ホーム画面のアイコンから開いたときと Safari で開いたときで保存データが別々になることがあります。

### ブラウザごとのID（`oshi-luna-device`）

- はじめて開いたときに、ブラウザの暗号用の乱数（`crypto.getRandomValues`）で32文字のランダムなIDを作り、localStorage に保存します（使えない古いブラウザでは普通の乱数で作ります）。次からは保存したIDを使います
- 名前・メールアドレス・端末の情報などは使いません。IDは今日の運勢の計算にだけ使い、サーバーに送ることも、画面・シェア画像・URL・共有文に出すこともありません
- ブラウザのデータを消すと、新しいIDになり、運勢の流れも変わります
- iPhone では、Safari とホーム画面に追加したアプリで保存場所が別になることがあり、そのときは別のIDになって、同じ日でも運勢がちがいます。別の端末・別のブラウザでも同様です
- localStorage が使えない環境（プライベートブラウズの一部・保存を止めている設定など）では、IDを保存できないため、日付だけで決まる全員共通の運勢を表示します（読み込むたびに運勢が変わらないようにするため）。この場合は個人差はありませんが、同じ日は同じ結果です
- 運勢は端末の時計（を日本時間に直した日付）で決まるので、端末の時計が大きくずれていると、その日付の運勢になります

### ホーム画面への追加

- はじめて診断を終えたときに一度だけ案内カードを表示（「あとで」か「追加方法を見る」を押すと、次からは出ません）
- トップの小さなリンク「📱 ホーム画面に追加する方法」からいつでも手順を見られます（ホーム画面から開いているときは出ません）
- 手順は iPhone の Safari／iPhone の Chrome など／LINE などのアプリ内ブラウザ／Android／その他 で出し分けます
- Android の Chrome などで、ブラウザがインストール画面を用意したときだけ「ホーム画面に追加する」ボタンを表示します

## 検索エンジン向けのファイル

- 公開URLは `https://oshi-luna.com/` として、`robots.txt` と `sitemap.xml` に書いています（このリポジトリには独自ドメインの設定ファイル `CNAME` はありません。Cloudflare などの管理画面で設定している場合も、そのドメインのいちばん上（`https://oshi-luna.com/robots.txt`）で開けることを確認してください）
- `sitemap.xml` には公開しているページだけを入れます。診断・今日の占い・結果は同じページの中で切り替わるので、URL はトップと、タイプ一覧（`types/`）の2つです。お試し表示（`?preview-date=`）や診断結果のような、人ごと・一時的な表示は入れません
- ページを増やしたときは `sitemap.xml` に足し、`<lastmod>` を更新してください（`node tests/check.js` で、すべての HTML が入っているか、存在しないページや ? のつくURLが入っていないかを確認します）
- `index.html` の `<head>` に、title・description・canonical（`https://oshi-luna.com/`）・OGP・構造化データ（WebSite）を入れています。お試し表示（`?preview-date=`）や GitHub Pages のアドレスで開いたときも、正式なURLは canonical の1つです
- トップは短く：ルナとキャッチコピー → 推し活タイプ診断のカード → 今日の推し活占い → 8つのタイプ（絵とタイプ名）→ よくある質問（3つ）。診断済みの人には、今日の占いのボタンを診断カードより先に出します（`app.js` の `refreshTop`）
- くわしい説明は `types/index.html`（8つのタイプの特徴・サブタイプコードの4つの傾向・診断のしくみ・よくある質問）。トップの8タイプの絵から、そのタイプの説明へ移動できます
- `types/index.html` のタイプの文章（名前・キャッチ・性格・輝くところ）と4つの傾向の説明は `js/data.js` と同じ文章です。データを直したときは、このページも同じように直してください（`node tests/check.js` が、文章のずれ・問題数・リンク切れ・各ページの title／description／canonical／OGP を確認します）
- 「無料」は、サービス全体のキャッチコピーにはしません。title・description・OGP には入れず、診断ボタンの下の案内とよくある質問で、今の機能が無料で使えることだけを伝えます

## アクセス解析（Google Analytics 4）

- `index.html` の `<head>` のいちばん上に、GA4 の公式タグ（gtag.js、測定ID `G-GW3MQNMW58`）を1回だけ入れています
- 計測するのはページを開いたとき（ページビュー）だけです。診断・今日の占い・結果は同じページの中で切り替わるので、切り替えのたびには計測しません。診断の答えや結果、占いの記録は送っていません
- ページを増やしたときは、同じタグを新しいページの `<head>` にも1回だけ入れてください（`node tests/check.js` で、すべての HTML に1回だけあるかを確認します）
- 広告ブロックなどで gtag.js が読み込めなくても、サイトはそのまま動きます。Service Worker は外部のファイルを扱わないので、gtag.js はキャッシュされません
- GitHub Pages のアドレスやローカルで開いたときも、同じ測定IDで計測されます
